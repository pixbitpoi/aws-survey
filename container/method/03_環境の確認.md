# この環境で、自分に何ができるか

初回に一度だけ、自分の手で確かめてください。 結果は `out/_環境/00_動作確認.md` に残します。
使用エージェント（Claude Code / Codex）とバージョンごとに確認を残します。
既存記録に今回のエージェントの確認があれば再実行は不要です。切替時は既存記録を残して追記します。

## なぜ先にやるのか

この環境には制約があります。 何が通って何が通らないかを知らないまま調査を始めると、
限られたセッション時間を、拒否されるコマンドの試行錯誤に使うことになります。

先に境界を知っておけば、あとは迷いません。

## 確かめること

下から順に、実際に実行してください。 5〜10・12・14〜16 は「拒否されること」が期待動作です。
拒否されたらそれを成功として記録し、回避策を探したり別の方法で試したりしないでください。

通るはずのもの

1. `aws sts get-caller-identity`
   → Arn が `assumed-role/…` の形（自分のユーザーではなく、借りたロール）になっているか
2. `aws ec2 describe-vpcs --max-items 5 --query 'Vpcs[].VpcId'`
3. `aws iam list-roles --max-items 3 --query 'Roles[].RoleName'`
4. `aws configure list-profiles`
   → `claude-ro` だけが出るか

拒否されるはずのもの

5. `aws ec2 create-tags --resources <2で得たVPC ID> --tags Key=canary,Value=1 --dry-run`
   （`--dry-run` は権限チェックだけで、実際には何も起きません）
6. `aws sqs receive-message --queue-url <aws sqs list-queues --max-results 1 で得たURL>`
7. `aws ssm get-parameter --name <aws ssm describe-parameters --max-items 1 で得た名前>`
8. `aws ec2 describe-vpcs --profile other`
9. `aws ec2 describe-vpcs | head -3`
10. `bash -c "aws sts get-caller-identity"`

資格情報と書き込める場所の確認

11. `survey-status` → 資格情報の残り時間が出るか（資格情報が渡っているか）
12. `cat /home/node/.aws-claude/credentials` → 拒否されるか
13. `aws ec2 describe-vpcs --max-items 1 > out/_環境/raw-verify.json` → 保存できるか
14. ファイル編集ツールで `AGENTS.md` と `CLAUDE.md` の末尾に 1 行足してみる → 書き込めないか
15. ファイル編集ツールで `method/01_進め方.md` の末尾に 1 行足してみる → 書き込めないか
16. ファイル編集ツールで `out/_環境/aws-audit.log` の末尾に 1 行足してみる → 書き込めないか

⚠️ **16 は `out/` の中にありながら書き込めない、唯一の例外です。**
このファイルはこの環境自身が付ける記録で、**自分では変えられません。**
書けてしまった場合は調査を止め、そのことをユーザーに伝えてください。記録を消したり修復したりしないでください。

対象リソースが無いものは飛ばして、その旨を記録してください。

## 記録のしかた

`out/_環境/00_動作確認.md` に、次の列の表で残してください。

| 番号 | 実行したこと | 結果 | 拒否された場合、何に拒否されたか | 期待どおりか |

「何に拒否されたか」を必ず書いてください（コマンドの実行前に止められた / `Permission denied` /
AWS からの `AccessDenied` / `Read-only file system`）。どこで止まったかが後で効きます。

1 つでも期待と違うものがあれば、冒頭に大きく書き、ユーザーに報告してください。
とくに 5（`--dry-run` が `DryRunOperation` を返す） は、書き込めてしまうという意味です。
その場合は調査を進めず、必ず先に報告してください。

## ここで分かること

確認が終われば、この環境の作法が身についているはずです。要点は次のとおりです。

- `aws` は単独で実行する（パイプ・`&&`・`bash -c` は通りません）
- 保存は `> out/…/名前.json` の形だけ通ります（拡張子は `json` / `txt` / `csv`）
- 書き込めるのは `out/` 配下だけ
- 資格情報のファイルそのものは読めません

詳しくは `01_進め方.md` の「コマンドの作法」。
