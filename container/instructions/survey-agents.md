# AWS インフラの調査

AWS を読み取り専用で調べ、このアカウントを初めて見る技術者に向けて「何をしていて、どう組まれていて、どこが気になるか」を
`out/report/` に書く環境。対象について分かるのは AWS API・`out/`・ユーザーの回答からだけで、事前の資料は無い。

## 仕事

- 最初の仕事は基礎調査。ユーザーに目的を聞いてから始めるのではなく、白紙で調べ、`out/report/構成報告.md` と
  `out/report/ユーザー確認事項.md` を書き切る。何を書くかは `method/報告.md`、どう調べるかは `method/調べ方.md`。
- `survey-status` に出ている経路（登録済みの EC2 ホスト・取り出してある Lambda のコード）は、聞かずに中を読んで報告に入れる（`method/経路.md`）。
- 報告があれば、以後はユーザーと対話で穴を埋める。質問にはその場で答え、依頼はその場でやる。事前の計画や承認は要らない。
  AWS の中で調べれば決まることは聞く前に調べ、聞くのは AWS の外のこと。
- 最初の指示に「ユーザーが応答できない」とある回は、聞かずにできることをすべてやって報告まで書き、聞きたいことは確認事項に書く。
  その回は一時キーが自動で入れ替わるので、残り時間で切り上げない。
- 監査・コスト削減・影響範囲のように基礎調査と性質の違う仕事を頼まれたら、成果物を `out/report/<仕事の名前>.md` に足す。

## 常に守ること

- AWS の作成・変更・削除を行わない。拒否された操作を回避しない。
- 事実と推測を分けて書く。推測は書いてよい（書かないと一覧になる）が、推測と分かる書き方にし、根拠を添える。
- 読めなかったもの・見ていないものは、そう書く。空白と「確認できなかった」は別物。
- 書けるのは `out/` だけ。`method/` と指示書は読み取り専用。`out/.survey/env/aws-audit.log` はこの環境の記録で、自分で触らない。
- 秘密の値はマスクする。Lambda の環境変数・EC2 の userData・`ec2` で読んだログ・`code/` のコードに接続情報が含まれうる。
- アカウント ID・ARN・IP アドレスの扱いはユーザーと話せる最初の機会に確認し、それまでは `out/` の外に出す文書に載せない。

## 開始

1. `survey-status` と `ls -A out/ out/.survey/ out/report/` を実行する（生データは `ls out/.survey/raw/`）。
2. `out/` が空なら `method/調べ方.md` の「最初の 1 回」から。あれば `out/.survey/state.md`（台帳）→ `out/report/ユーザー確認事項.md`
   の回答欄 → `out/report/構成報告.md` → `out/report/前提.md` → `out/.survey/notes.md` の順に読む。
3. 報告があるのに台帳に検証の記録が無ければ、最初の仕事は検証（`method/報告.md`「検証」）。ユーザーが先に何か聞いてきたら、そちらが先。

## 記録の置き場

| 場所 | 内容 |
| --- | --- |
| `out/report/構成報告.md` | 報告。人が読む。現在形で書き、履歴を残さず、間違いは本文を書き直す |
| `out/report/ユーザー確認事項.md` | ユーザーへの問い。回答欄にユーザーが書く。次の回はまずここを読む |
| `out/report/前提.md` | 対象について、ユーザーから聞いて分かったこと（出どころを添える） |
| `out/.survey/raw/` | API と `ec2` の生データ（`raw-` で始める）。仕事を跨いで共有し、同じ問いを叩き直さない |
| `out/.survey/state.md` | 台帳。作業・現在地・次にやること・未解決・決定事項の 5 見出し |
| `out/.survey/notes.md` | 次の回にも効く調べ方と読み違い |
| `out/.survey/log/` | 各回の判断と訂正の記録（`NN-<topic>.md` の英語名）。叩いたコマンドは監査ログにあるので列挙しない |
| `out/.survey/env/` | 動作確認（`check.md`）と監査ログ |

## 終了

台帳を更新し、分かったことは報告の本文に反映し、効いた調べ方を `notes.md` に残す。`ExpiredToken` が出たら書きかけを保存し、
台帳を更新してからユーザーに再発行を依頼する（「作業環境の外で `aws-survey credentials` を実行してください」）。
ユーザーには仕組みの言葉（台帳・統合版・raw）ではなく、何を調べ、何が分かり、何をしてほしいかで話す。
