# AWS インフラの調査

AWS を読み取り専用で調べる環境。対象について分かるのは AWS API・`out/`・ユーザーの回答からだけ。

## 開始・再開

1. `survey-status` と `ls out/` を実行する。
2. `method/00_開始と再開.md` の順序で、初回の準備または既存の記録の確認を行う。
3. 初回・セッション再開時に `method/01_進め方.md` を読む。基礎調査の報告が済んでいれば `method/02_基礎調査のあと.md` も。
4. 初回または使用エージェントを切り替えたときは `method/03_環境の確認.md` で動作を確認する。

最初の仕事は基礎調査（`method/04_基礎調査の型.md`）。ユーザーに目的や対象の説明を聞いてから始めるのではなく、白紙で調べ、
生データを `raw/` に集め、報告を `report/` に書き切る。
最初の指示に「ユーザーが応答できない」とある回は、`method/00` の「ユーザーが応答できない回」に従い、聞かずに報告まで書いて終える。
その回は一時キーが自動で入れ替わるので、残り時間で切り上げない。
報告があれば、以後はユーザーと対話しながら穴を埋める（`method/02`）。質問にはその場で答え、依頼はその場でやる。
AWS の中で調べれば決まることは、聞く前に調べる。聞くのは AWS の外のこと。
統合版は書いた回とは別のセッションで検証する（`method/05_報告の検証.md`）。
ユーザーが自分から伝えた情報は `out/01_システム概要.md` に残す。
登録済みの EC2 ホスト（`survey-status` に出る）の中は `ec2 <host> <動詞>` で調べる（`method/06_EC2の中を調べる.md`）。
取り出してある Lambda のコード（`survey-status` に出る）は `code/` にある（`method/07_Lambdaのコードを読む.md`）。
どちらも足すのはこの環境の外の操作。頼むときは `method/06` / `method/07` にある依頼文をそのまま使う。

## 常に守ること

- AWS の作成・変更・削除を行わない。拒否された操作を回避しない。
- 調査文書を書けるのは `out/` だけ。`method/` と指示書は読み取り専用。
- `out/_環境/aws-audit.log` は環境の記録。自分で編集・削除しない。
- いま何の作業をしているかは `out/00_進捗.md` が正。ユーザーの指示はそれより優先する。
- 基礎調査では評価や提案を書かない（`method/04`）。監査などを頼まれたら、その仕事では評価が成果物になる（`method/02`）。
- 分からないことは推測で埋めず、事実と推測を分けて書く。ユーザーにしか分からないことは聞いて、回答を記録する。
- 秘密の値はマスクする。Lambda 環境変数や EC2 userData には接続情報が含まれうる。`ec2` で読んだログ本文、`code/` のコードも同じ。
- アカウント ID・ARN・IP アドレスの扱いは、ユーザーと話せる最初の機会に確認する。それまでは `out/` の外に出す文書に載せない。

## 記録の置き場

| 場所 | 内容 |
| --- | --- |
| `out/00_進捗.md` | 全体の台帳。現在の作業・背景・決定 |
| `out/01_システム概要.md` | 対象について、ユーザーから聞いて分かったこと |
| `out/02_調査ノウハウ.md` | 次にも効く調べ方と読み違い |
| `out/_環境/` | 動作確認と環境の記録 |
| `out/<作業>/02_進捗.md` | その作業の台帳 |
| `out/<作業>/raw/` | API 生データ |
| `out/<作業>/log/` | 各回の調査記録 |
| `out/<作業>/report/` | 人に渡す統合版・ユーザー確認事項・検証記録 |

`raw/` → `log/` → `report/` の順にまとめる。統合版の本文は現在形で書き、訂正履歴や「第 N 回」を入れない。
過去の仕事の `report/` は読み、書き換えない。既存データを再利用し、同じ AWS 問い合わせを繰り返さない。

## 終了・期限切れ

環境は使い捨てで、調査の引き継ぎは `out/` に残す。
残り時間の判断は `survey-status` の表示に従い、固定の分数を決めない。
終了時は全体・作業の台帳を更新し、効いた調べ方も保存する。
`ExpiredToken` が出たら書きかけを保存し、台帳を更新してからユーザーに再発行を依頼する。
