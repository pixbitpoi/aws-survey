# AWS インフラの調査

AWS を読み取り専用で調べる環境。対象について分かるのは AWS API・`out/`・ユーザーの回答からだけ。

## 開始・再開

1. `survey-status` と `ls out/` を実行する。
2. `method/00_開始と再開.md` の順序で、初回の準備または既存台帳の確認を行う。
3. 初回・セッション再開時に `method/01_進め方.md` と `method/02_フェーズとは.md` を読む。
4. 初回または使用エージェントを切り替えたときは `method/03_環境の確認.md` で動作を確認する。

初回の目的確認では、何を明らかにしたいかだけを聞く。対象の説明を先に求めない。
基礎調査は `method/04_基礎調査の型.md` に従い、白紙で棚卸しする。
統合版は書いた回とは別のセッションで検証する（`method/05_報告の検証.md`）。
ユーザーが自分から伝えた情報は `out/01_システム概要.md` に残す。
登録済みの EC2 ホスト（`survey-status` に出る）の中は `ec2 <host> <動詞>` で調べる（`method/06_EC2の中を調べる.md`）。

## 常に守ること

- AWS の作成・変更・削除を行わない。拒否された操作を回避しない。
- 調査文書を書けるのは `out/` だけ。`method/` と指示書は読み取り専用。
- `out/_環境/aws-audit.log` は環境の記録。自分で編集・削除しない。
- 現在のフェーズは `out/00_進捗.md` が正。作業はそのフェーズの `00_目的と規則.md` に沿う。
- 目的と規則はユーザーが承認してから調査を始める。承認済みの内容を独断で変更しない。
- 前のフェーズの制限を持ち込まない。範囲外の発見は全体台帳の「次のフェーズに送るもの」に残す。
- 分からないことは推測で埋めず、ユーザーに質問して回答を記録する。
- 秘密の値はマスクする。Lambda 環境変数や EC2 userData には接続情報が含まれうる。`ec2` で読んだログ本文も同じ。
- アカウント ID・ARN・IP アドレスの扱いは最初にユーザーに確認する。

## 記録の置き場

| 場所 | 内容 |
| --- | --- |
| `out/00_進捗.md` | 全体の台帳。現在のフェーズ・背景・決定 |
| `out/01_システム概要.md` | 対象について分かったこと |
| `out/02_調査ノウハウ.md` | 次にも効く調べ方と読み違い |
| `out/_環境/` | 動作確認と環境の記録 |
| `out/<フェーズ>/00_目的と規則.md` | 目的・範囲・成果物・完了条件 |
| `out/<フェーズ>/01_調査項目.md` / `02_進捗.md` | 調査一覧とそのフェーズの台帳 |
| `out/<フェーズ>/raw/` | API 生データ |
| `out/<フェーズ>/log/` | 各回の調査記録 |
| `out/<フェーズ>/report/` | 人に渡す統合版・ユーザー確認事項・検証記録 |

`raw/` → `log/` → `report/` の順にまとめる。統合版の本文は現在形で書き、訂正履歴や「第 N 回」を入れない。
過去フェーズは読み、書き換えない。既存データを再利用し、同じ AWS 問い合わせを繰り返さない。

## 終了・期限切れ

環境は使い捨てで、調査の引き継ぎは `out/` に残す。
残り時間の判断は `survey-status` の表示に従い、固定の分数を決めない。
終了時は全体・フェーズの台帳を更新し、効いた調べ方も保存する。
`ExpiredToken` が出たら書きかけを保存し、台帳を更新してからユーザーに再発行を依頼する。
